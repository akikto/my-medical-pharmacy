1. WEEKLY SALES CHART
Add a "Weekly Sales" option/card on Home.

Requirements:
- Show sales for the current week, day by day.
- Use actual saved sales from the local database.
- Show at least:
  - Mon
  - Tue
  - Wed
  - Thu
  - Fri
  - Sat
  - Sun
- Show sales amount in INR (₹).
- If there are no sales on a day, show ₹0.
- Prefer a clean bar/line chart consistent with the existing Home visual design.
- Add a "View Sales" action that opens the existing Sales History page.
- Do not change existing Sales History logic.

2. TODAY'S ORDER LIST
Add a "Today's Order List" option/card on Home.

Purpose:
The pharmacy owner should be able to create a list of medicines/items that need to be ordered from wholesalers today and then share that list through WhatsApp or export it as PDF.

Requirements:
- Create an order-list workspace using the existing medicine/inventory data.
- Allow adding medicines to today's order list.
- For each order item support:
  - Medicine name
  - Strength/form if available
  - Quantity to order
  - Optional supplier/wholesaler
  - Optional note
- Allow editing quantity and removing items.
- Show total number of order items.
- Save today's order list locally so it survives app restart.
- Allow marking an item as ordered.
- Provide:
  - "Share via WhatsApp"
  - "Export PDF"
  - "Print" if the existing native print capability is available
  - "Clear Today's Order List"
- WhatsApp sharing must use the user's installed/default WhatsApp mechanism or an appropriate wa.me/share URL; do not build a separate messaging system.
- PDF must be generated locally/offline and contain:
  - Pharmacy name
  - Date
  - Medicine/item list
  - Quantities
  - Supplier/wholesaler where available
  - Notes where available
- Do not send any data to a third-party server.
- If WhatsApp is not installed/available, show a clear fallback instead of failing silently.

3. WHOLESALER / ORDER CONTACTS
Add a "Wholesalers & Order Contacts" option on Home.

Requirements:
- Create a simple local contact list for pharmacy wholesalers/suppliers.
- Reuse the existing Supplier data where possible instead of creating duplicate supplier records.
- Each contact may contain:
  - Supplier/Wholesaler name
  - Contact person
  - Phone number
  - WhatsApp number if different
  - Address
  - Notes
- Provide search.
- Provide Add/Edit/Delete.
- Provide direct "Call" action using the device/OS phone mechanism where available.
- Provide "WhatsApp" action using WhatsApp where available.
- Do not create an internal calling/SMS system.
- Existing Supplier records and supplier workflows must continue to work unchanged.

4. ACCOUNTS / BUSINESS DATA RESET
Add a carefully protected "Reset Accounts/Data" option under Settings or an appropriate admin-only area, and provide a shortcut from Home if appropriate.

IMPORTANT SAFETY REQUIREMENTS:
- Do NOT make this a one-click destructive action.
- Require an explicit confirmation dialog.
- Clearly explain exactly what will be deleted/reset before confirmation.
- Require a second confirmation for the final destructive action.
- Require the user to type a confirmation phrase such as:
  RESET MY DATA
- Automatically create a backup before reset.
- If backup creation fails, abort the reset.
- Never delete the application itself, database schema, settings required for the app to run, or medicine master data unless the user explicitly selects that scope.
- Prefer separate reset scopes:
  A. Reset sales/accounting transaction history
  B. Reset purchase/accounting transaction history
  C. Reset customer/supplier dues if supported
  D. Reset all transactional/business history
- Keep medicine master data and core configuration by default.
- Show a final summary of what was reset.
- Make the operation transactional/atomic so a partial reset cannot leave inconsistent data.
- After reset, refresh all dashboard totals, reports, stock calculations, sales history, purchase history, and account balances.
- Do not silently delete backups.
- Do not affect production data during development/testing.
