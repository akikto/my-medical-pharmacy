B. GST / TAX

Add proper GST support for sales.

Requirements:
- GST should be calculated from the existing medicine/product data where possible.
- Support GST rate per product/batch if the existing model can safely support it.
- Do not invent a tax rate.
- Support common Indian GST rates through configurable product data rather than hard-coding one rate for every medicine.
- Clearly separate:
  - taxable amount
  - CGST
  - SGST
  - IGST if the application configuration requires it
  - total GST
  - final invoice total
- Preserve rounding consistency.
- Store the GST values used at sale time so historical invoices do not change if the product's GST setting changes later.
- Existing invoices must remain readable.

If the current database does not have enough information to safely support GST, create the smallest safe migration required.

C. CUSTOMER MASTER

Create a dedicated Customer page/service.

- Phone number
- Optional address
- Optional notes
- Active/inactive status if useful

Requirements:

- Existing customers should auto-suggest while typing in POS.

- Avoid duplicate customer records where possible.
- Do not make customer login/authentication necessary.

D. CREDIT / DUE KHATA

Payment mode "Credit" must create a customer receivable.

Create a dedicated:
"Due Khata" / customer credit management page.

For each customer show:
- Customer name
- Phone
- Total credit
- Amount paid
- Current outstanding due

Transaction/ledger view:
- Invoice/date
- Debit/credit amount
- Payment/collection
- Running balance
- Notes

Requirements:
- A credit sale increases customer due.
- A customer payment decreases customer due.
- Partial payments must be supported.
- Full settlement must be supported.
- Do not allow a payment to reduce the balance below zero.
- Every due/payment change must be auditable through the ledger.
- Historical sale amounts must not be silently modified.
- Customer deletion must be protected if financial transactions exist.
- Prefer deactivate/archive over destructive deletion when transaction history exists.

E. CUSTOMER DUE COLLECTION

Add "Collect Payment" action.

Requirements:
- Select customer.
- Show current outstanding balance.
- Enter payment amount.
- Payment mode.
- Optional note.
- Save payment.
- Update balance immediately.
- Show transaction in ledger.
- Prevent invalid/negative amounts.
- Use a transaction so partial writes cannot leave inconsistent balances.

F. UPI

Settings:
- UPI ID
- Optional pharmacy display name

POS:
- Payment mode "UPI"
- Show configured UPI ID.
- Generate a standard UPI payment QR/deep-link using the configured UPI ID and current invoice amount where supported.
- Allow entering/storing UPI Transaction ID/reference number.
- Transaction ID must be associated with the invoice/payment.
- Do not claim that a payment was actually received merely because a QR was displayed.
- Payment confirmation remains the user's responsibility unless a verified payment integration is added later.
