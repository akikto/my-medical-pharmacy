Redesign and implement the Home / Dashboard page of my existing
“My Medical Pharmacy” Windows desktop pharmacy management software.

IMPORTANT:
Use the attached reference image as the PRIMARY VISUAL DESIGN REFERENCE.
Recreate the same overall professional look, layout hierarchy, spacing,
card structure, sidebar style, colors, typography, and information density,
but DO NOT blindly copy the image or invent functionality that does not exist
in the application.

GOAL:
Create a polished, professional, modern Indian pharmacy-management
dashboard suitable for a real Windows desktop application.

==================================================
1. FIRST: INSPECT THE EXISTING PROJECT
==================================================

Before making any code changes:

- Inspect the complete existing project structure.
- Identify the current Home/Dashboard page.
- Identify the existing routing/navigation system.
- Identify existing database models/services/APIs.
- Identify existing medicine, inventory, batch, purchase, sales,
  supplier, customer, billing, GST/report, notification and settings data.
- Identify existing reusable UI components.
- Identify the existing theme, fonts, icons and design system.
- Understand how the local/offline database works.
- Do NOT create duplicate database logic.
- Do NOT create duplicate business logic.
- Reuse existing APIs, hooks, services, queries and components wherever possible.

Do not modify unrelated pages unless required for the Dashboard navigation
to work correctly.

==================================================
2. IMPORTANT FUNCTIONALITY RULE
==================================================

This is a UI/UX redesign, NOT a rewrite of the pharmacy system.

DO NOT remove existing functionality.

DO NOT change existing business rules.

DO NOT change database schemas unless absolutely necessary.

DO NOT change existing routes unnecessarily.

DO NOT replace working functionality with dummy/static data.

Every Dashboard number/card/table must use REAL DATA from the existing
application/database wherever that data already exists.

If a required metric does not currently exist, first determine whether it
can safely be calculated from existing data.

Do not invent fake backend APIs just to make the UI look complete.
