You are a senior desktop systems and full-stack engineer. Build a fully offline, production-grade Medicine Inventory and POS desktop application using Tauri v2, React (TypeScript), Tailwind CSS, Lucide icons, and embedded SQLite via `@tauri-apps/plugin-sql`.

### Technical Architecture & Core Rules
1. Zero Cloud Dependency: Fully offline, data stored in a local SQLite database (`pharmacy.db`).
2. Performance Target: Instant response, low memory footprint, cold start under 2s.
3. Code Quality: Production-ready, fully typed TypeScript. No placeholder functions, no half-baked "// TODO" comments.

### Database Schema (SQLite)
Create and auto-migrate these tables on startup:
- `medicines` (id INTEGER PK AUTOINCREMENT, name TEXT NOT NULL, generic_name TEXT, company TEXT, rack_location TEXT, min_stock_alert INTEGER DEFAULT 10, created_at DATETIME DEFAULT CURRENT_TIMESTAMP)
- `medicine_batches` (id INTEGER PK AUTOINCREMENT, medicine_id INTEGER NOT NULL REFERENCES medicines(id) ON DELETE CASCADE, batch_no TEXT NOT NULL, expiry_date TEXT NOT NULL, purchase_rate REAL NOT NULL, mrp REAL NOT NULL, sale_rate REAL NOT NULL, current_stock INTEGER NOT NULL DEFAULT 0, barcode TEXT)
- `suppliers` (id INTEGER PK AUTOINCREMENT, name TEXT NOT NULL, phone TEXT, address TEXT, balance_due REAL DEFAULT 0)
- `purchases` (id INTEGER PK AUTOINCREMENT, invoice_no TEXT NOT NULL, supplier_id INTEGER REFERENCES suppliers(id), total_amount REAL NOT NULL, purchase_date TEXT NOT NULL)
- `purchase_items` (id INTEGER PK AUTOINCREMENT, purchase_id INTEGER REFERENCES purchases(id), batch_id INTEGER REFERENCES medicine_batches(id), quantity INTEGER NOT NULL, rate REAL NOT NULL, total REAL NOT NULL)
- `sales` (id INTEGER PK AUTOINCREMENT, invoice_no TEXT UNIQUE NOT NULL, customer_name TEXT, customer_phone TEXT, subtotal REAL NOT NULL, discount REAL DEFAULT 0, grand_total REAL NOT NULL, payment_mode TEXT DEFAULT 'CASH', created_at DATETIME DEFAULT CURRENT_TIMESTAMP)
- `sale_items` (id INTEGER PK AUTOINCREMENT, sale_id INTEGER REFERENCES sales(id), batch_id INTEGER REFERENCES medicine_batches(id), quantity INTEGER NOT NULL, unit_price REAL NOT NULL, total_price REAL NOT NULL)

### Functional Modules
1. FEFO-Driven POS & Billing:
   - Search medicines by name, generic name, or USB barcode scan.
   - First Expiry, First Out (FEFO) logic: auto-select the non-expired batch with the nearest expiry date.
   - Keyboard-first interaction: F2 focuses search, Arrow keys navigate results, Enter adds to cart, F9 finishes sale and calculates cash/change return, ESC clears cart.
   - Stock deduction within a database transaction when sale completes.
2. Inventory & Batch Management:
   - Add/edit medicine master and batch records.
   - Visual alerts for expired items and items expiring within 30/60/90 days.
   - Low stock alerts based on `min_stock_alert`.
3. Stock-in & Purchases:
   - Distributor purchase entry adding new batches and incrementing inventory stock counts.
4. Auto Backup:
   - Export SQLite database file to a local backup folder on exit or via single-click trigger.
